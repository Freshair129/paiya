# ป้ายยา (paiya)
## เอกสารข้อกำหนดผลิตภัณฑ์ (PRD)

**รุ่น 0.1 · 6 พฤศจิกายน 2026 · ร่างสำหรับเริ่มพัฒนา**

### 1. เป้าหมายและผู้ใช้

ผู้ซื้ออุปกรณ์ไอทีมือสองต้องเปิดหลายกลุ่ม อ่านคอมเมนต์ไล่ตามสถานะ และจำเองว่าเคยเห็นผู้ขายหรือราคาใกล้เคียงกันที่ไหน ป้ายยารวมประกาศจากกลุ่มที่เลือกไว้ ให้ค้นสินค้า ดูราคาเสนอขาย ติดตามประกาศ และตรวจหลักฐานที่มาของข้อมูลได้จากเครื่องเดียว

ผู้ใช้หลักของ MVP คือผู้ซื้อหนึ่งคนที่ติดตามไม่เกิน 5 กลุ่ม ราคาหลักเป็นบาท และหน้าแอปแสดงเวลาประเทศไทย ผู้ใช้ค้นผ่านหน้าเว็บบนมือถือหรือใช้ Agent ที่ได้รับสิทธิ์อ่านข้อมูลในเครื่อง ผู้ซื้อยังคงติดต่อผู้ขายและทำรายการที่ต้นทาง

### 2. เส้นทางการใช้งาน

1. เปิด **กลุ่ม** เลือกกลุ่มที่อนุญาตให้เก็บข้อมูล ตั้งรอบ 30 หรือ 60 นาที แล้วอ่านผลตรวจรอบแรก หากยืนยันลำดับโพสต์ล่าสุดไม่ได้ กลุ่มนั้นจะแสดงข้อจำกัดทันที
2. เปิด **สินค้า** ค้น “RTX 3060 12GB” กรองงบและสถานะ การ์ดแสดงภาพ รุ่น ราคา สถานะ และเวลาตรวจ การแตะการ์ดเปิดรายละเอียดสินค้ากับลิงก์ต้นทาง
3. แตะ **ติดตาม** เพื่อตรวจโพสต์เดิมโดยตรง เมื่อระบบเห็นความเปลี่ยนแปลง หน้า **ติดตาม** จะแสดงเหตุการณ์ใหม่ หากรอบตรวจกระทบข้อจำกัดแหล่งข้อมูล ผู้ใช้จะเห็นเวลาตรวจสำเร็จครั้งล่าสุด
4. แตะสถานะเพื่อดูคำยืนยันของผู้ขายหรือป้ายต้นทางพร้อมเวลาที่เก็บหลักฐาน แตะชื่อผู้ขายเพื่อดูประกาศก่อนหน้าและช่วงเวลาที่ระบบมีข้อมูล
5. ผู้ใช้ถาม Agent เช่น “มี 3060 12GB ต่ำกว่า 6,000 ที่ยังไม่มีคำยืนยันปิดขายไหม” คำตอบต้องอ้างประกาศ แสดงเวลาตรวจล่าสุด และเปิดภาพที่เก็บไว้ได้ ผลลัพธ์อาจรวมประกาศที่ยังยืนยันสถานะไม่ได้ จึงต้องแสดงสถานะของแต่ละรายการ

### 3. ข้อกำหนดและลำดับส่งมอบ

P0 หมายถึงข้อที่ต้องผ่านก่อนเปิดใช้กับผู้ซื้อ P1 หมายถึงฟังก์ชันที่ตามหลังเส้นทางหลักแต่ยังอยู่ในขอบเขต MVP ระยะ A ใช้ชุดหน้าเว็บและเหตุการณ์ทดสอบที่รู้คำตอบล่วงหน้า ระยะ B ใช้ระบบชุดเดียวกันกับกลุ่มจริงที่มีสิทธิ์เก็บข้อมูลอัตโนมัติ

| ID | สิ่งที่ผู้ใช้ต้องทำได้ | ลำดับ / รุ่น |
|---|---|---|
| PR-01 | เพิ่ม หยุดชั่วคราว เปิดต่อ หรือนำกลุ่มออกจากรายการติดตามได้สูงสุด 5 กลุ่ม ตั้งรอบค้นประกาศใหม่แยกกลุ่มที่ 30 หรือ 60 นาที และเห็นเวลาตรวจสำเร็จล่าสุด | P0 · A/B |
| PR-02 | เลือกการแสดงโพสต์ล่าสุดและตรวจผลการเรียงก่อนเก็บ หากหน้าไม่ให้เลือกหรือยืนยันไม่ได้ ให้แสดง “ยืนยันลำดับล่าสุดไม่ได้” พร้อมเวลาตรวจ ผู้ใช้แยกแยะรอบสำเร็จ รอบได้ข้อมูลบางส่วน และรอบขาดหายได้ | P0 · A/B |
| PR-03 | ดูประวัติการเปลี่ยนสถานะ กลับมาขายใหม่ และจำนวนคอมเมนต์ตามที่สังเกตได้ ระบบใช้ป้ายสถานะของประกาศหรือคำยืนยันที่ระบุตัวผู้ขายได้เป็นหลักฐาน คอมเมนต์ “CF” จากผู้สนใจเป็นเหตุการณ์ความสนใจ การเข้าดูโพสต์ไม่ได้เป็นสถานะการเข้าถึง | P0 · A/B |
| PR-04 | เปิดลิงก์โพสต์และภาพย่อหรือภาพจับเฉพาะส่วนพร้อมเวลาเก็บหลักฐานจากหน้ารายละเอียดได้ ภาพที่ใช้ยืนยันสถานะต้องอ่านใจความสำคัญได้ ถ้าภาพขาด ให้บอกว่า “ไม่มีภาพหลักฐานในรอบนี้” และยังเปิดหลักฐานข้อความที่มีได้ | P0 · A/B |
| PR-05 | แตะผู้ขายเพื่อดูวันแรกและวันล่าสุดที่พบ กลุ่มที่พบ จำนวนประกาศอ้างอิงได้ และรายการที่ผู้ขายแจ้งปิดขาย ตัวเลขเปิดดูโพสต์ที่นับได้ ใช้รหัสหรือลิงก์โปรไฟล์ที่ยืนยันได้ ผู้ขายชื่อซ้ำ ผู้โพสต์นิรนาม และประกาศข้ามกลุ่มที่จับคู่ไม่ได้ ให้คงความไม่แน่ใจไว้ | P0 · A/B |
| PR-06 | ค้นและกรองประกาศตามรุ่น ราคา สถานะ และกลุ่ม บันทึกติดตาม แล้วเปิดหลักฐานหรือต้นทางบนมือถือได้ อนุญาตให้ขอตรวจโพสต์ที่ติดตามทุก 10 นาทีภายใต้งบการเข้าถึงที่กำหนด เมื่อเกินงบให้เลื่อนงานพร้อมแสดงเวลาตรวจจริง | P0 · A/B |
| PR-07 | เห็นแท็กรุ่นย่อย ความจุ สภาพ และประเภทของราคา พร้อมหลักฐานที่ใช้สกัด ฟิลด์ที่คลุมเครือแสดง “ยังระบุไม่ได้” ใช้ Agent ในเครื่องค้นรายการ ประวัติ และภาพจากคลังแบบอ่านอย่างเดียวได้ เมื่อโมเดลหยุดทำงานยังค้นรายการที่จัดเก็บแล้วได้ | P1 · A/B |
| PR-08 | ดูแนวโน้มราคาเสนอขายย้อนหลังของสินค้าที่เทียบกันได้ พร้อมค่ามัธยฐาน จำนวนตัวอย่าง ช่วงเวลา และกลุ่มที่ครอบคลุม หากตัวอย่างไม่ถึงเกณฑ์ให้แสดง “ข้อมูลยังน้อย” ขั้นคำนวณต้องกันมัดจำ ค่าผ่อน ค่าส่ง ของเสีย ชุดรวม และราคาที่ไม่มีหน่วยเทียบออกจากชุดเปรียบเทียบตามความเหมาะสม | P1 · A/B |
| PR-09 | เมื่อสิทธิ์หมดอายุหรือถูกเพิกถอน ระบบหยุดเก็บจากกลุ่มนั้น แจ้งเหตุผลและเวลาตรวจครั้งสุดท้าย ผู้ใช้สั่งลบข้อมูลในขอบเขตที่เลือกได้ การลบต้องครอบคลุมรายการ หลักฐาน และมุมมองที่อ้างอิง ผ่านทั้งหน้าแอปและ Agent | P0 · A/B |

โพสต์ใหม่ที่ยังไม่ปิดขายอยู่ในคิวตรวจตามรอบกลุ่มใน 24 ชั่วโมงแรกตามงบที่มี ผู้ใช้เก็บรายการโปรดไว้ดูได้ตลอด และเปิดรอบเร่ง 10 นาทีให้รายการที่สนใจเป็นพิเศษได้ครั้งละ 24 ชั่วโมง สูงสุด 10 รายการพร้อมกัน ค่าเหล่านี้เป็นข้อเสนอสำหรับทดสอบบน PC เครื่องเดียว

### 4. ภาษาที่ใช้กับสถานะและผู้ขาย

| กรณีที่พบ | ข้อความตัวอย่างในแอป |
|---|---|
| โพสต์อายุ 5 ชั่วโมง แสดง 5 คอมเมนต์ ระบบเปิดอ่านได้ 3 รายการ | “โพสต์เมื่อ 5 ชม. · ตรวจเมื่อ 12 นาทีที่แล้ว” และ “ต้นทางแสดง 5 ความคิดเห็น · อ่านได้ 3” หากไม่เห็นจำนวนผู้คอมเมนต์ที่ยืนยันได้ ให้ละตัวเลขผู้แสดงความเห็น |
| ผู้สนใจเขียน “รับครับ” ยังไม่มีคำตอบจากผู้ขาย | “มีผู้สนใจ · ยังไม่พบการยืนยันจองจากผู้ขาย” |
| ผู้ขายแจ้งว่าจองแล้ว ต่อมาผู้ซื้อยกเลิกและผู้ขายเปิดขายอีกครั้ง | “กลับมาเปิดขาย · พบคำยืนยันเมื่อ 14:20 น.” แตะดูได้ทั้งเหตุการณ์ใหม่และประวัติการจอง |
| ผู้ขายแจ้ง “ปิดการขาย” | “ผู้ขายแจ้งปิดขาย” พร้อมเวลาและหลักฐาน การจ่ายเงินจริงและราคาปิดยังไม่ทราบ |
| ระบบเพิ่งพบผู้ขายและราคาอยู่ต่ำกว่าตลาดที่สังเกต | โปรไฟล์แสดง “พบครั้งแรกวันนี้ในกลุ่มที่ติดตาม” ส่วนหน้า *ประกาศ* แสดงผลเปรียบเทียบราคาพร้อมจำนวนตัวอย่าง ไม่มีคะแนนความซื่อสัตย์จากราคาและความถี่ในการโพสต์ |
| ตรวจรอบ 09:00 สำเร็จ แต่รอบ 09:30 เข้าไม่ได้ | “ตรวจสำเร็จล่าสุด 09:00 น. · รอบ 09:30 น. เข้าโพสต์ไม่ได้” เมื่อพบสถานะใหม่รอบถัดไปให้แสดงเวลาที่พบ เวลาที่ผู้ขายเปลี่ยนสถานะจริงอาจไม่ทราบ |

### 5. รูปแบบหน้าจอ

แถบหลักมี **สินค้า · ติดตาม · กลุ่ม** หน้าแรกให้พื้นที่กับภาพ ชื่อรุ่นและราคา วางสถานะกับเวลาตรวจไว้ติดกัน ตัวกรองเปิดเป็นแผงจากด้านล่าง หน้าประกาศเรียงจากสินค้า ผู้ขาย ประวัติสถานะ ไปถึงหลักฐาน กราฟราคาย้อนหลังอยู่ในรายละเอียดรุ่น และประวัติการทำงานของตัวเก็บข้อมูลอยู่ที่หน้ากลุ่ม

บนโทรศัพท์ที่เชื่อมต่อเครื่องหลัก ใช้การเชื่อมต่อส่วนตัวที่มี HTTPS และการยืนยันตัวตน ค่าเริ่มต้นบนเครื่องหลักเปิดแอปผ่าน localhost ได้

ใช้พื้นเรียบ ตัวอักษรไทยอ่านง่าย ระยะห่างสม่ำเสมอ และสีเน้นหลักสีเดียว ใช้ข้อความหรือไอคอนกำกับสีทุกสถานะ พื้นที่แตะอย่างน้อย 44 × 44 CSS px เมื่อรูปหายให้คงพื้นที่แสดงสินค้า ผลค้นหาว่างให้แสดงตัวกรองที่ใช้และปุ่มล้าง ตัวอย่างข้อความถูกตัดได้เฉพาะในการ์ดและต้องอ่านเต็มได้ในหน้ารายละเอียด

### 6. เกณฑ์ตรวจรับที่เสนอ

ตารางนี้เป็นเป้าหมายของรุ่น 0.1 ต้องบันทึกผลทดสอบก่อนใช้ตัดสินผ่าน

| วิธีทดสอบ | เกณฑ์ยอมรับ |
|---|---|
| ระยะ A ใช้ชุดทดสอบที่ติดป้ายคำตอบโดยคนอย่างน้อย 100 กรณี ครอบคลุมโพสต์ซ้ำ ชื่อซ้ำ ผู้ซื้อพูดว่าปิดขาย การเปิดขายใหม่ รูปหาย และช่วงขาดการตรวจ วัดเฉพาะประกาศที่ปรากฏในขอบเขตหน้าและการเลื่อนที่กำหนด | พบอย่างน้อย 95% ของประกาศที่เข้าเกณฑ์และมองเห็นในชุดทดสอบ นำชุดเดิมเข้าซ้ำแล้วจำนวนประกาศและเหตุการณ์ธุรกิจเท่าเดิม |
| เทียบผลการระบุสถานะ ผู้ขาย และราคากับคำตอบอ้างอิง | ปิดขายผิด 0 กรณี ผูกผิดผู้ขาย 0 กรณี ราคาและหน่วยถูกอย่างน้อย 95% ของชุดย่อยที่ระบุราคาเสนอขายชัดเจน รายงานจำนวนที่ระบบงดตัดสินแยกด้วย |
| ให้ผู้ใช้ค้นสินค้าที่กำหนด เปิดหลักฐานที่รองรับสถานะ แล้วทดสอบซ้ำบนหน้าจอกว้าง 360 CSS px | จากรายการถึงหลักฐานไม่เกิน 3 ครั้งที่แตะ ไม่มีการเลื่อนแนวนอนของหน้า สถานะไทย ปุ่ม และเวลาตรวจอ่านได้ ใช้แป้นพิมพ์เข้าถึงรายการ หลักฐาน และต้นทางได้ |
| ทดสอบ 5 กลุ่มด้วยรอบ 30 และ 60 นาที ระงับสิทธิ์ 1 กลุ่ม ทำให้รอบตรวจล้มเหลว และส่งงานติดตามเกินงบ | กลุ่มที่ถูกระงับหยุดเก็บ กลุ่มอื่นทำงานต่อได้ รอบล้มเหลวไม่อัปเดตเวลาสำเร็จล่าสุด งานที่เกินงบไม่ทำให้ระบบเข้าแหล่งข้อมูลเกินขีดจำกัด |
| ระยะ B ให้ผู้ทดสอบบันทึกรายการที่มองเห็นจริง เวลา ลำดับ และขอบเขตการเลื่อน เทียบผลกับ Collector ในรอบเดียวกัน | รายงานผลแยกจากผลชุดทดสอบ ระบุจำนวนกลุ่ม รอบ ตัวอย่าง การเรียงที่ยืนยันได้ และข้อมูลที่ขาด ต้องทบทวนทุกกรณีที่ผูกผิดคนหรือปิดขายผิดก่อนขยายการใช้งาน |

### 7. ขอบเขตรุ่นถัดไปและเงื่อนไขการเปิดใช้

**ระยะ A — ระบบในเครื่อง** ส่งมอบเส้นทางครบจากชุดทดสอบไปถึงรายการ หลักฐาน การค้นด้วย Agent และแนวโน้มราคาเสนอขาย ระบบต้องนำข้อมูลทดสอบมาเล่นซ้ำและตรวจคำตอบเทียบได้

**ระยะ B — กลุ่มจริงที่ได้รับอนุญาต** เปิด Collector เฉพาะแหล่งที่มีสิทธิ์เก็บข้อมูลอัตโนมัติและตรวจการจัดการข้อมูลล็อกอินผ่านแล้ว เริ่มจากหนึ่งกลุ่ม ตรวจผลระบุผู้ขาย สถานะ ภาพ และภาระเครื่อง แล้วขยายได้สูงสุดห้ากลุ่ม หากสิทธิ์หรือความพร้อมยังไม่ครบ ให้ใช้รุ่น A สาธิตและตรวจรับส่วนอื่นต่อได้

**หลัง MVP** ประเมิน GenesisBlockDB เมื่อมีคำค้นที่ต้องตามความสัมพันธ์หลายทอด เช่น สินค้ารุ่นเดียวกันที่ปรากฏซ้ำข้ามผู้ขายหรือกลุ่ม โดยเก็บหมายเลขอ้างอิงกลับหลักฐานเดิม ส่วนคำพยากรณ์ขาขึ้นหรือขาลงต้องระบุตลาด ช่วงพยากรณ์ และตัวแปรเป้าหมายก่อน ทดสอบย้อนหลังตามลำดับเวลา เทียบวิธีใช้ราคามัธยฐานล่าสุด และเผยช่วงความไม่แน่นอนก่อนเปิดให้ผู้ซื้อใช้

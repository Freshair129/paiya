# ป้ายยา (paiya)
## เอกสารข้อกำหนดผลิตภัณฑ์ (PRD)

**รุ่น 0.2 · 7 พฤศจิกายน 2026 · ข้อเสนอสำหรับพัฒนาและทดสอบ MVP**

### 1. เป้าหมายและผู้ใช้

ผู้ซื้ออุปกรณ์ไอทีมือสองต้องเปิดหลายกลุ่ม อ่านคอมเมนต์ไล่ตามสถานะ และจำเองว่าเคยเห็นผู้ขายหรือราคาใกล้เคียงกันที่ไหน ป้ายยาให้ผู้ซื้อบันทึกสเปกที่กำลังหา เก็บประกาศที่พบ และเทียบดีลก่อนทักผู้ขาย โดยย้อนดูข้อความที่รองรับราคาและสถานะได้ การค้นพบโพสต์ใหม่จากกลุ่มโดยอัตโนมัติเปิดเฉพาะแหล่งที่ผ่านเงื่อนไขระยะ B

ผู้ใช้หลักของ MVP คือผู้ซื้อหนึ่งคนที่ติดตามไม่เกิน 5 กลุ่ม ราคาหลักเป็นบาท และหน้าแอปแสดงเวลาประเทศไทย ผู้ใช้ค้นผ่านหน้าเว็บบนมือถือหรือใช้ Agent ที่ได้รับสิทธิ์อ่านข้อมูลในเครื่อง ผู้ซื้อยังคงติดต่อผู้ขายและทำรายการที่ต้นทาง

### 2. เส้นทางการใช้งาน

1. ในหน้า **ติดตาม** ผู้ซื้อตั้งรับ “RTX 3060 12GB ราคาเสนอขายไม่เกิน 6,000 บาท สภาพใช้งานได้ เฉพาะการ์ดแยกชิ้น” ก่อนพบประกาศ ดูเงื่อนไขที่บันทึกไว้และรายการเดิมที่ตรงได้ทันที
2. เมื่อพบโพสต์ในกลุ่มที่ใช้ข้อมูลได้ ผู้ซื้อกด **เพิ่มประกาศ** วางลิงก์กับข้อความจากโพสต์ แนบภาพได้ตามสิทธิ์ ตรวจรายการ ราคา และบรรทัดที่ใช้แยกราคา แล้วกดยืนยัน หน้าแอปแสดง “ผู้ใช้ส่งล่าสุด …” และเปิดลิงก์ต้นทางเมื่อผู้ซื้อเลือก
3. เมื่อได้ข้อความใหม่ของโพสต์เดิม ผู้ซื้อเพิ่มข้อมูลรอบใหม่ เช่น ราคา 3060 ลดจาก 6,300 เป็น 5,800 บาท หน้า **ติดตาม** แจ้งดีลเข้าเงื่อนไขพร้อมเหตุผลและหลักฐาน ผู้ซื้อเลือกติดตามเฉพาะ 3060 ได้แม้ในโพสต์มี 3070 ด้วย
4. ในหน้า **สินค้า** ผู้ซื้อเลือก 2–3 ชิ้นเพื่อเทียบราคา ค่าส่ง ประกัน สภาพ และสถานะ แตะดูผู้ขายและหลักฐาน แล้วเปิดต้นทางเพื่อทักผู้ขาย
5. สำหรับกลุ่มที่เปิดตัวเก็บอัตโนมัติได้ ผู้ซื้อตั้งรอบ 30 หรือ 60 นาทีในหน้า **กลุ่ม** ดูการเรียงโพสต์ล่าสุด ความครอบคลุม และเวลาตรวจสำเร็จ หากเลือกเร่งตรวจรายการที่ติดตาม ให้แสดงรอบที่ทำได้จริง
6. ผู้ใช้ถาม Agent เช่น “มี 3060 12GB ต่ำกว่า 6,000 ที่ยังไม่มีคำยืนยันปิดขายไหม” คำตอบอ้างกลับไปรายการและหลักฐาน แสดงสถานะ พร้อมที่มาและเวลาของข้อมูลล่าสุดที่มีสิทธิ์อ่าน

### 3. ข้อกำหนดและลำดับส่งมอบ

P0 คือพฤติกรรมที่ต้องผ่านก่อนเปิดเส้นทางที่ระบุ P1 ตามหลังเส้นทางหลัก ระยะ A พัฒนาและตรวจด้วยข้อมูลสังเคราะห์ ระยะ M ทดลองให้ผู้ซื้อส่งข้อมูลเอง ระยะ B ทดลองค้นโพสต์และกลับไปตรวจโดยอัตโนมัติเฉพาะกลุ่มที่ได้รับสิทธิ์

| ID | สิ่งที่ผู้ใช้ต้องทำได้ | ลำดับ / รุ่น |
|---|---|---|
| PR-01 | เพิ่ม หยุดชั่วคราว เปิดต่อ หรือนำกลุ่มออกจากรายการติดตามได้สูงสุด 5 กลุ่ม ตั้งรอบค้นประกาศใหม่แยกกลุ่มที่ 30 หรือ 60 นาที และเห็นเวลาตรวจสำเร็จล่าสุด | P0 · A/B |
| PR-02 | เลือกการแสดงโพสต์ล่าสุดและตรวจผลการเรียงก่อนเก็บ หากหน้าไม่ให้เลือกหรือยืนยันไม่ได้ ให้แสดง “ยืนยันลำดับล่าสุดไม่ได้” พร้อมเวลาตรวจ ผู้ใช้แยกแยะรอบสำเร็จ รอบได้ข้อมูลบางส่วน และรอบขาดหายได้ | P0 · A/B |
| PR-03 | ดูประวัติการเปลี่ยนสถานะ กลับมาขายใหม่ และจำนวนคอมเมนต์ตามที่สังเกตได้ ระบบใช้ป้ายสถานะของประกาศหรือคำยืนยันที่ระบุตัวผู้ขายได้เป็นหลักฐาน คอมเมนต์ “CF” จากผู้สนใจเป็นเหตุการณ์ความสนใจ การเข้าดูโพสต์ไม่ได้เป็นสถานะการเข้าถึง | P0 · A/M/B |
| PR-04 | เปิดลิงก์โพสต์และภาพย่อหรือภาพจับเฉพาะส่วนพร้อมเวลาเก็บหลักฐานจากหน้ารายละเอียดได้ ภาพที่ใช้ยืนยันสถานะต้องอ่านใจความสำคัญได้ ถ้าภาพขาด ให้บอกว่า “ไม่มีภาพหลักฐานในรอบนี้” และยังเปิดหลักฐานข้อความที่มีได้ | P0 · A/M/B |
| PR-05 | แตะผู้ขายเพื่อดูวันแรกและวันล่าสุดที่พบ กลุ่มที่พบ จำนวนประกาศอ้างอิงได้ และรายการที่ผู้ขายแจ้งปิดขาย ตัวเลขเปิดดูโพสต์ที่นับได้ ใช้รหัสหรือลิงก์โปรไฟล์ที่ยืนยันได้ ผู้ขายชื่อซ้ำ ผู้โพสต์นิรนาม และประกาศข้ามกลุ่มที่จับคู่ไม่ได้ ให้คงความไม่แน่ใจไว้ | P0 · A/M/B |
| PR-06 | ค้นและกรองประกาศตามรุ่น ราคา สถานะ และกลุ่ม บันทึกติดตาม แล้วเปิดหลักฐานหรือต้นทางบนมือถือได้ สำหรับแหล่งที่มีสิทธิ์เก็บอัตโนมัติ อนุญาตให้ขอตรวจโพสต์ที่ติดตามทุก 10 นาทีภายใต้งบการเข้าถึงที่กำหนด เมื่อเกินงบให้เลื่อนงานพร้อมแสดงเวลาตรวจจริง | P0 · A/M/B |
| PR-07 | เห็นแท็กรุ่นย่อย ความจุ สภาพ และประเภทของราคา พร้อมหลักฐานที่ใช้สกัด ฟิลด์ที่คลุมเครือแสดง “ยังระบุไม่ได้” ใช้ Agent ในเครื่องค้นรายการ ประวัติ และภาพจากคลังแบบอ่านอย่างเดียวได้ เมื่อโมเดลหยุดทำงานยังค้นรายการที่จัดเก็บแล้วได้ | P1 · A/M/B |
| PR-08 | ดูแนวโน้มราคาเสนอขายย้อนหลังของสินค้าที่เทียบกันได้ พร้อมค่ามัธยฐาน จำนวนตัวอย่าง ช่วงเวลา และกลุ่มที่ครอบคลุม หากตัวอย่างไม่ถึงเกณฑ์ให้แสดง “ข้อมูลยังน้อย” ขั้นคำนวณต้องกันมัดจำ ค่าผ่อน ค่าส่ง ของเสีย ชุดรวม และราคาที่ไม่มีหน่วยเทียบออกจากชุดเปรียบเทียบตามความเหมาะสม | P1 · A/M/B |
| PR-09 | เมื่อสิทธิ์หมดอายุหรือถูกเพิกถอน ระบบหยุดเก็บจากกลุ่มนั้น แจ้งเหตุผลและเวลาตรวจครั้งสุดท้าย ผู้ใช้สั่งลบข้อมูลในขอบเขตที่เลือกได้ การลบต้องครอบคลุมรายการ หลักฐาน และมุมมองที่อ้างอิง ผ่านทั้งหน้าแอปและ Agent | P0 · A/M/B |
| PR-10 | เพิ่มประกาศจากลิงก์ตรงพร้อมข้อความ ดูตัวอย่างแล้วค่อยบันทึก แนบภาพเป็นหลักฐานได้ภายใต้สิทธิ์ เมื่อส่งข้อความใหม่จากโพสต์เดิม ผู้ซื้อเห็นข้อมูลรอบใหม่กับประวัติก่อนหน้า การเพิ่มประกาศทำได้โดยที่แอปไม่เปิดต้นทาง | P0 · A/M |
| PR-11 | บันทึก แก้ไข พัก และเปิดกฎตั้งรับตามรุ่นย่อย ความจุ งบ สภาพ และสิ่งที่ตัดออก ดูดีลเดิมที่ตรงได้ เมื่อพบชิ้นใหม่หรือชิ้นเดิมกลับเข้าเงื่อนไข ให้เห็นเหตุผลในกล่องแจ้งเตือนภายในแอปเพียงครั้งเดียว | P0 · A/M/B |
| PR-12 | ติดตามทั้งโพสต์หรือเฉพาะชิ้น ดูการลดราคา การติดจอง หรือการกลับมาเปิดขายของชิ้นที่เลือก การเร่งตรวจโพสต์ที่มีหลายชิ้นใช้รอบเดียวภายใต้สิทธิ์ของแหล่ง | P1 · A/M/B |
| PR-13 | เปรียบเทียบ 2–3 ชิ้นจากประกาศที่มีสิทธิ์อ่าน แสดงราคาเสนอขาย ค่าส่ง ยอดรวมที่คำนวณได้ สภาพ ประกันที่ผู้ขายระบุ สถานะและเวลาล่าสุด พร้อมทางเปิดหลักฐาน ถ้ายังไม่รู้ค่าส่งให้แสดง “ยังไม่ทราบยอดรวม” | P1 · A/M/B |

สำหรับการตรวจอัตโนมัติ โพสต์ใหม่ที่ยังไม่ปิดขายอยู่ในคิวตรวจตามรอบกลุ่มใน 24 ชั่วโมงแรกตามงบที่มี ผู้ใช้เก็บรายการโปรดไว้ดูได้ตลอด และเปิดรอบเร่ง 10 นาทีให้รายการที่สนใจเป็นพิเศษได้ครั้งละ 24 ชั่วโมง สูงสุด 10 รายการพร้อมกัน ค่าเหล่านี้เป็นข้อเสนอสำหรับทดสอบบน PC เครื่องเดียว

### 4. ภาษาที่ใช้กับสถานะและผู้ขาย

| กรณีที่พบ | ข้อความตัวอย่างในแอป |
|---|---|
| โพสต์อายุ 5 ชั่วโมง แสดง 5 คอมเมนต์ ระบบเปิดอ่านได้ 3 รายการ | “โพสต์เมื่อ 5 ชม. · ตรวจเมื่อ 12 นาทีที่แล้ว” และ “ต้นทางแสดง 5 ความคิดเห็น · อ่านได้ 3” หากไม่เห็นจำนวนผู้คอมเมนต์ที่ยืนยันได้ ให้ละตัวเลขผู้แสดงความเห็น |
| ผู้สนใจเขียน “รับครับ” ยังไม่มีคำตอบจากผู้ขาย | “มีผู้สนใจ · ยังไม่พบการยืนยันจองจากผู้ขาย” |
| ผู้ขายแจ้งว่าจองแล้ว ต่อมาผู้ซื้อยกเลิกและผู้ขายเปิดขายอีกครั้ง | “กลับมาเปิดขาย · พบคำยืนยันเมื่อ 14:20 น.” แตะดูได้ทั้งเหตุการณ์ใหม่และประวัติการจอง |
| ผู้ขายแจ้ง “ปิดการขาย” | “ผู้ขายแจ้งปิดขาย” พร้อมเวลาและหลักฐาน การจ่ายเงินจริงและราคาปิดยังไม่ทราบ |
| ระบบเพิ่งพบผู้ขายและราคาอยู่ต่ำกว่าตลาดที่สังเกต | โปรไฟล์แสดง “พบครั้งแรกวันนี้ในกลุ่มที่ติดตาม” ส่วนหน้า *ประกาศ* แสดงผลเปรียบเทียบราคาพร้อมจำนวนตัวอย่าง ไม่มีคะแนนความซื่อสัตย์จากราคาและความถี่ในการโพสต์ |
| ตรวจรอบ 09:00 สำเร็จ แต่รอบ 09:30 เข้าไม่ได้ | “ตรวจสำเร็จล่าสุด 09:00 น. · รอบ 09:30 น. เข้าโพสต์ไม่ได้” เมื่อพบสถานะใหม่รอบถัดไปให้แสดงเวลาที่พบ เวลาที่ผู้ขายเปลี่ยนสถานะจริงอาจไม่ทราบ |

### 5. รูปแบบหน้าจอ

แถบหลักมี **สินค้า · ติดตาม · กลุ่ม** หน้าแรกให้พื้นที่กับภาพ ชื่อรุ่นและราคา วางสถานะกับเวลาตรวจไว้ติดกัน ตัวกรองเปิดเป็นแผงจากด้านล่าง หน้าประกาศเรียงจากสินค้า ผู้ขาย ประวัติสถานะ ไปถึงหลักฐาน กราฟราคาย้อนหลังอยู่ในรายละเอียดรุ่น และประวัติการทำงานของตัวเก็บข้อมูลอยู่ที่หน้ากลุ่ม

วางปุ่ม **เพิ่มประกาศ** ในหน้า **สินค้า** หน้าตั้งรับกับกล่องแจ้งเตือนอยู่ใน **ติดตาม** ผู้ซื้อเลือกสินค้าจากหน้ารายการเข้าแผง **เปรียบเทียบ** ได้ บนมือถือให้แสดงหนึ่งหัวข้อพร้อมค่าของทุกดีลที่เลือก เช่น “ค่าส่ง” กับข้อมูลของแต่ละร้าน เพื่ออ่านครบที่ความกว้าง 360 CSS px

บนโทรศัพท์ที่เชื่อมต่อเครื่องหลัก ใช้การเชื่อมต่อส่วนตัวที่มี HTTPS และการยืนยันตัวตน ค่าเริ่มต้นบนเครื่องหลักเปิดแอปผ่าน localhost ได้

ใช้พื้นเรียบ ตัวอักษรไทยอ่านง่าย ระยะห่างสม่ำเสมอ และสีเน้นหลักสีเดียว ใช้ข้อความหรือไอคอนกำกับสีทุกสถานะ พื้นที่แตะอย่างน้อย 44 × 44 CSS px เมื่อรูปหายให้คงพื้นที่แสดงสินค้า ผลค้นหาว่างให้แสดงตัวกรองที่ใช้และปุ่มล้าง ตัวอย่างข้อความถูกตัดได้เฉพาะในการ์ดและต้องอ่านเต็มได้ในหน้ารายละเอียด

### 7. ขอบเขตรุ่นถัดไปและเงื่อนไขการเปิดใช้

**ระยะ A — ระบบในเครื่อง** ส่งมอบเส้นทางครบจากชุดทดสอบไปถึงรายการ หลักฐาน การค้นด้วย Agent และแนวโน้มราคาเสนอขาย ระบบต้องนำข้อมูลทดสอบมาเล่นซ้ำและตรวจคำตอบเทียบได้

**ระยะ M — ผู้ซื้อส่งประกาศเอง** หลังตรวจสิทธิ์ การลบ และเส้นทางนำเข้าบน fixture แล้ว ผู้ซื้อใช้ข้อความที่ได้รับอนุญาตให้บันทึกเพื่อทดสอบการตั้งรับ การแจ้งเตือน และการเทียบดีล กำหนดแหล่งและอายุจัดเก็บก่อนรับข้อมูล ภาพที่แนบใช้เปิดดูเป็นหลักฐาน การอ่านข้อความจากภาพด้วย OCR ต้องมีชุดทดสอบภาษาไทยก่อนนำมาใช้ตัดสินราคาและสถานะ

**ระยะ B — กลุ่มจริงที่ได้รับอนุญาต** เปิด Collector เฉพาะแหล่งที่มีสิทธิ์เก็บข้อมูลอัตโนมัติและตรวจการจัดการข้อมูลล็อกอินผ่านแล้ว เริ่มจากหนึ่งกลุ่ม ตรวจผลระบุผู้ขาย สถานะ ภาพ และภาระเครื่อง แล้วขยายได้สูงสุดห้ากลุ่ม ระหว่างที่รอสิทธิ์เก็บอัตโนมัติ ให้ประเมินเส้นทางส่งเองตามเงื่อนไขระยะ M

**หลัง MVP** ประเมิน GenesisBlockDB เมื่อมีคำค้นที่ต้องตามความสัมพันธ์หลายทอด เช่น สินค้ารุ่นเดียวกันที่ปรากฏซ้ำข้ามผู้ขายหรือกลุ่ม โดยเก็บหมายเลขอ้างอิงกลับหลักฐานเดิม ส่วนคำพยากรณ์ขาขึ้นหรือขาลงต้องระบุตลาด ช่วงพยากรณ์ และตัวแปรเป้าหมายก่อน ทดสอบย้อนหลังตามลำดับเวลา เทียบวิธีใช้ราคามัธยฐานล่าสุด และเผยช่วงความไม่แน่นอนก่อนเปิดให้ผู้ซื้อใช้

# ADR 0002 แหล่งข้อมูลเมื่อยังไม่มีสิทธิ์เก็บอัตโนมัติ

**วันที่** 6 พฤศจิกายน 2026
**สถานะ** **ร่าง** รอ Product owner และ Tech lead ตัดสินคำถามท้ายเอกสาร
**เกี่ยวข้อง** [ADR 0001](0001-observation-store.md) · [PRD ข้อ 7](../../product/PRD.md) · [SPEC ข้อ 6–7](../SPEC.md)

## บริบท

PRD ระยะ B เปิด Collector เฉพาะแหล่งที่ได้รับอนุญาตให้เก็บข้อมูลอัตโนมัติจากแพลตฟอร์ม ข้อกำหนดของ Meta ห้ามเข้าถึงหรือเก็บข้อมูลด้วยวิธีอัตโนมัติหากไม่ได้รับอนุญาตล่วงหน้า ([Meta Automated Data Collection Terms](https://www.facebook.com/legal/automated_data_collection_terms)) การได้รับสิทธิ์อนุญาตจากผู้ดูแลกลุ่มไม่เท่ากับสิทธิ์จากแพลตฟอร์ม และ Collector ที่ล็อกอินด้วยบัญชีจริงมีความเสี่ยงที่บัญชีจะถูกระงับ

ผลคือเส้นทางหลักของ PRD ขั้น 1–3 (ค้นโพสต์ใหม่ตามรอบและตรวจ permalink ซ้ำ) อาจไม่มีวันเปิดกับกลุ่มจริง ขณะที่แผนปัจจุบันมีเพียงทางออก “ใช้รุ่น A สาธิต” ซึ่งไม่มีผู้ซื้อคนใดใช้งานจริงได้ เอกสารนี้ไม่ใช่ความเห็นทางกฎหมาย เจ้าของโครงการควรตรวจข้อกำหนดฉบับปัจจุบันและขอคำปรึกษาก่อนตัดสินใจระยะ B

## ทางเลือก

| ทางเลือก | ใช้กับผู้ซื้อจริงได้เมื่อไร | ข้อดี | ข้อเสีย |
|---|---|---|---|
| 1. รอสิทธิ์จากแพลตฟอร์ม (แผนเดิม) | เมื่อได้รับสิทธิ์เป็นลายลักษณ์อักษร | ได้ฟีเจอร์ครบตาม PRD | ไม่มีกำหนดเวลาและอาจไม่ได้เลย |
| 2. ผู้ใช้นำเข้าเอง | หลังระยะ A | ระบบไม่เข้าถึงแพลตฟอร์มเอง ใช้ pipeline เดิมตั้งแต่ตรวจ schema ถึง evidence | ไม่มีการค้นโพสต์ใหม่และการตรวจซ้ำอัตโนมัติ ผู้ใช้ต้องส่งข้อมูลซ้ำเพื่ออัปเดตสถานะ |
| 3. แหล่งที่มีช่องทางอนุญาตชัดเจน | หลังประเมินแหล่ง | อาจได้การติดตามอัตโนมัติจริง | ต้องเขียน adapter ใหม่ ตลาดอาจไม่ตรงกลุ่มผู้ใช้ |

ทางเลือก 2 หมายถึงผู้ใช้วางลิงก์ คัดลอกข้อความโพสต์และคอมเมนต์ หรือส่งภาพหน้าจอเข้าแอป ระบบไม่เปิดลิงก์นั้นเอง ข้อความเข้าตัวแยกกฎและ Ollama ตามเดิม ภาพหน้าจอต้องใช้ OCR หรือโมเดลภาพในเครื่องซึ่งยังไม่มี benchmark แต่ละครั้งที่ผู้ใช้ส่งเป็นหนึ่ง observation ที่มี `source_kind` ใหม่ ส่วนการตัดสินสถานะ หลักฐาน ประวัติผู้ขาย และ MCP ใช้กติกาเดิม

## ข้อเสนอ

ใช้ทางเลือก 2 เป็นเส้นทางสู่การใช้งานจริงของ MVP คง live adapter ไว้หลัง feature flag ที่ปิดเริ่มต้นตาม SPEC ข้อ 6 เพื่อให้ทางเลือก 1 ยังเปิดได้เมื่อมีสิทธิ์ แล้วประเมินทางเลือก 3 หลัง MVP

## ผลต่อเอกสารเมื่อรับข้อเสนอ

ยังไม่แก้ใน PR ที่เพิ่ม ADR ฉบับนี้ เพราะเป็นการเปลี่ยนขอบเขตที่เจ้าของต้องตัดสินก่อน

- PRD เพิ่ม PR ใหม่สำหรับการนำเข้าโดยผู้ใช้และปรับข้อ 7 ให้ระยะ B เป็นทางเลือกเสริม
- SRS เพิ่ม FR/AT สำหรับการนำเข้า การกันข้อมูลซ้ำเมื่อผู้ใช้ส่งโพสต์เดิม และความแม่นยำของ OCR
- เพิ่ม `manual_share` ใน `source_kind` ของ [observation.v1.schema.json](../contracts/observation.v1.schema.json) พร้อม fixture
- PR-01, PR-02 และการเร่งรอบ 10 นาทีใน PR-06 ใช้กับแหล่งที่มีการเก็บอัตโนมัติเท่านั้น หน้าแอปต้องแสดงว่ารายการใดอัปเดตล่าสุดจากการส่งของผู้ใช้

## คำถามที่รอคำตอบ

1. ผู้ซื้อจะยังได้ประโยชน์พอหรือไม่ถ้าไม่มีการค้นโพสต์ใหม่อัตโนมัติ และควรวัดด้วยอะไร
2. MVP รับเฉพาะข้อความที่คัดลอกมา หรือต้องรองรับภาพหน้าจอตั้งแต่แรก
3. เกณฑ์ความแม่นยำของการสกัดจากภาพหน้าจอเป็นเท่าไร และใช้ชุดทดสอบใด
4. จะยื่นขอสิทธิ์ตามทางเลือก 1 หรือไม่ และใครเป็นผู้ติดตาม

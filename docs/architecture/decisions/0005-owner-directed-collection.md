# ADR 0005 การเก็บข้อมูลอัตโนมัติตามคำตัดสินของเจ้าของ

**สถานะ** รับรองแล้ว · ผู้ตัดสินใจคือเจ้าของรีโป (Product owner + Tech lead) · เสนอและรับรอง 9 พฤศจิกายน 2026 ตามคำสั่งของเจ้าของในแชต ([PR #93](https://github.com/Freshair129/paiya/pull/93)) · แทนที่ข้อกำหนดเรื่องสิทธิ์จากแพลตฟอร์มใน [ADR 0002](0002-source-strategy.md) ข้อ “โจทย์ที่ต้องตัดสิน” และข้อ 3 ของ “ขอบเขตที่เสนอสำหรับรุ่น 0.2” เฉพาะส่วนที่ระบุด้านล่าง ส่วนอื่นของ ADR 0002 ยังใช้ต่อ

**หมายเหตุสถานะปัจจุบัน** ข้อ 3 เรื่องตำแหน่ง Collector ถูกแทนที่ด้วย [ADR 0006](0006-collector-monorepo.md); ขอบเขตและกติกาอื่นใน ADR นี้ยังใช้ต่อ

## โจทย์

ADR 0002 กำหนดให้ Collector ระยะ B ต้องมีทั้งสิทธิ์จากแพลตฟอร์มและสิทธิ์ใช้งานกลุ่มก่อนเปิดใช้ เจ้าของรีโปแจ้งว่าโครงการนี้ไม่ห้ามการเก็บข้อมูลอัตโนมัติ และให้ Collector ส่งผลเข้า paiya ผ่าน [สัญญา inbox](../contracts/collector-inbox.md) การรับรองครั้งแรกระบุให้พัฒนา Collector นอกรีโป แต่เจ้าของเปลี่ยนคำตัดสินเรื่องตำแหน่งภายหลังตาม [ADR 0006](0006-collector-monorepo.md) ADR นี้บันทึกว่ากติกาใดเปลี่ยน และกติกาใดยังคงไว้

## คำตัดสินที่เสนอ

1. **เงื่อนไขเปิดใช้** การมีหลักฐานสิทธิ์จากแพลตฟอร์มไม่ใช่เงื่อนไขของรีโปนี้อีกต่อไป
   - เจ้าของตัดสินใจเองเป็นรายกลุ่ม
   - เจ้าของบันทึกขอบเขต วัตถุประสงค์ (ใช้ซื้อของส่วนตัว) และ retention ใน grant ของ paiya
2. **การรับความเสี่ยง** เจ้าของรับทราบและยอมรับความเสี่ยงเอง เอกสารของรีโปต้องระบุตรงตามจริง ไม่อ้างว่าแพลตฟอร์มอนุญาต
   - [Meta Automated Data Collection Terms](https://www.facebook.com/legal/automated_data_collection_terms) ห้ามเก็บอัตโนมัติโดยไม่ได้รับอนุญาตเป็นลายลักษณ์อักษร
   - การเก็บอาจทำให้บัญชีถูกจำกัดหรือระงับ
3. **ตำแหน่งของ Collector (แทนที่โดย ADR 0006)** โค้ดอยู่ใน paiya monorepo ส่วน Collector ยังรันเป็น process แยก paiya ไม่เปิดหรือส่งคำขอไปยังแหล่งต้นทาง และรับข้อมูลผ่าน inbox เท่านั้น
4. **กติกาที่คงไว้ทั้งหมด**
   - ห้ามใช้เครื่องมือหรือเทคนิคหลบการตรวจจับบอท stealth browser หรือปลอม fingerprint
   - หยุดทันทีเมื่อพบหน้าให้ล็อกอิน checkpoint หรือ challenge และเคารพ `Retry-After` ([SPEC](../SPEC.md) ข้อ 3 และ 6)
   - เก็บเท่าที่จำเป็นตาม SRS ข้อ 6 ทั้งข้อความที่เกี่ยวกับสถานะและภาพครอป ใช้ grant การเพิกถอน การลบ และ replay ตามเดิม เพราะข้อมูลในกลุ่มเป็นข้อมูลส่วนบุคคลของสมาชิก
   - ทดสอบการแยก session (ข้อมูลรับรองต้องไม่ส่งข้าม origin) ก่อนรันกับกลุ่มจริง
   - ข้อมูลจริงไม่เข้า commit, Issue, PR หรือไฟล์แนบสาธารณะ
5. **การอนุมัติงานในรีโป** งานใน paiya ที่รับหรือบันทึกข้อมูล `facebook_live` ยังเป็นงานความเสี่ยงสูงตาม AGENTS.md ต้องได้คำอนุมัติของเจ้าของใน Issue ก่อนเริ่ม แต่ไม่ต้องแนบหลักฐานสิทธิ์จากแพลตฟอร์ม ให้แนบคำตัดสินและขอบเขตตามข้อ 1 แทน

## ทางเลือกที่ไม่เลือก

- **คงเงื่อนไขสิทธิ์จากแพลตฟอร์มตาม ADR 0002** ปลอดภัยที่สุดทั้งด้านเงื่อนไขการใช้งานและบัญชี แต่ทำให้ Collector เปิดใช้ไม่ได้ในทางปฏิบัติ
- **ยกเลิกทุกข้อกำหนด รวมถึงข้อห้ามหลบการตรวจจับ** ไม่เลือก เพราะเจ้าของไม่ได้สั่ง และเพิ่มความเสี่ยงต่อบัญชีกับข้อมูลโดยไม่จำเป็น

## เมื่อควรทบทวน

ทบทวนเมื่อแพลตฟอร์มแจ้งเตือนหรือจำกัดบัญชี เมื่อมีผู้ใช้มากกว่าหนึ่งคน เมื่อจะเผยแพร่หรือแบ่งปันข้อมูลที่เก็บ หรือเมื่อได้สิทธิ์อย่างเป็นทางการ

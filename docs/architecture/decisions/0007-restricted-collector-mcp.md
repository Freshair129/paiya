# ADR 0007: Restricted MCP transport for Collector

Status: implementation candidate under [Issue #91 owner approval](https://github.com/Freshair129/paiya/issues/91#issuecomment-6937280955), pending independent review. Synthetic verification does not authorize or establish a live pilot.

## Problem and evidence

The isolated browser prototype imported the upstream MCP server. That exposed tools outside the Collector guard, retained broad response capture, and inherited profile cleanup behavior. Its screenshot check compared URL, permalink and rectangle; replacing a card or image node at the same rectangle could pass. A PID preflight was not an exclusive profile lease.

Synthetic probes also showed that removing Cookie/Referer from `Fetch.continueRequest` headers did not reliably remove browser credentials. Explicit empty headers prevented outgoing canaries in the tested browser, but external response `Set-Cookie` still changed the profile, including when filtered with `Fetch.continueResponse`. That technique is not an isolation boundary.

## Decision

- Keep Collector as the existing separate process and inbox v1 producer. Add the optional `discover-browser --transport mcp` path; keep the existing Playwright path as the default. `discover-mcp-synthetic` validates explicit localhost configuration and separate marked synthetic runtime paths without patching live validation.
- Pin `browserstealthmcp==0.3.4` in the Collector lockfile. Reuse only `stealth_browser_mcp.cdp_raw.raw_command` through the pinned nodriver CDP transport. Run Paiya's own MCP SDK stdio service with exactly six Collector tools. Do not import or launch the upstream MCP server, browser manager, launcher, hooks, response-body capture, cookie tools or stealth behavior. This is not an upstream-server compatibility claim.
- Start ordinary visible Chrome with a closed, dedicated, owner-marked profile. Hold an OS file lock and retain the exact subprocess handle. Refuse unknown ownership, junction/symlink paths, existing DevTools markers, everyday profiles, and running profile users. Preserve the profile and its files. Close only the process created by the service; no PID/profile-wide kill or deletion is permitted. EOF, cancellation and operation failures close the owned browser before releasing the lease.
- Install request interception before first navigation. All documents, including redirects and child documents, must stay in the configured group path or its login/challenge paths on the exact origin. New page targets are refused; source workers remain paused until per-session guards are installed. Browser-level Fetch interception covers worker entry/update scripts before a worker target exists. Observe status and Retry-After at response receipt without retaining response bodies or credentials. A 429 latches a maximum deadline, or manual resume when any header is unusable.
- By default, deny cross-origin subresources. Optional `asset_origins` names at most eight exact origins. Only browser-requested static Image/Stylesheet/Font/Script GETs without request bodies qualify. Intercept them before the browser sends anything. A separate bounded HTTP client is new for every asset and redirect hop; it receives no browser headers, cookies, credentials or proxy settings; the fixed Origin header is derived solely from the validated source origin. Check each redirect origin, scheme, host encoding and loop; enforce a four-hop, 12-second and 8-MiB raw/decoded-body limit. Deliver the verified static body, Content-Type, decoded length, `Cache-Control: no-store` and only the upstream Access-Control-Allow-Origin/Credentials, Cross-Origin-Resource-Policy and X-Content-Type-Options headers. Missing/restrictive CORS remains missing/restrictive; no permissive headers are fabricated. Do not deliver Set-Cookie, authentication, Location or other response state. This relay is narrow static delivery, not a hidden endpoint reader or a network response archive.
- Read challenge state before cards in one synchronous isolated-world evaluation. Bind snapshot evidence to the exact document, card and image nodes. Mutation records reject relevant card, style, attribute, ancestor and security UI changes, including replacement and restoration. Ordinary text updates outside those nodes may proceed. URL/rectangle equality alone is insufficient. Never publish evidence after document, transport or guard uncertainty.

## Profile workflow and limits

The existing Playwright transport attaches to a manually opened dedicated browser. MCP owns its browser lifecycle, so the owner must sign in with an ordinary dedicated browser, then close that browser before MCP can acquire it. MCP never signs in, copies cookies, resolves challenges, takes over an active browser, or removes an unknown/stale DevTools marker. A prior DevTools marker remains protected for owner review.

This candidate contains a live configuration path, but its verification is synthetic. No real profile, Facebook page, real group mapping or real data has been used. Live selectors, CDN allowlists, rendered-source behavior, manual sign-in/profile reuse, active-grant validity at execution, and source-specific completeness remain pilot prerequisites. Static relay failures stop conservatively; credential-dependent assets, Brotli-only delivery, opaque frames and arbitrary cache-dependent flows remain unsupported. The static relay intentionally disables caching and cookie state while preserving the listed upstream CORS/CORP restrictions.

## Acceptance and alternatives

Requirements: FR-01/02/03/07/13; acceptance subsets: AT-01/02/04/09. See [traceability](../../quality/TRACEABILITY.md), the [Collector spec](../external-collector.md), [policy tests](../../../collector/tests/test_mcp_policy.py), [asset tests](../../../collector/tests/test_mcp_assets.py), and [native MCP harness](../../../collector/scripts/test-mcp-browser.py).

Rejected: importing and filtering the upstream server after startup; mutating a global installed package; profile-wide process cleanup; screenshot checks based only on URL/rectangle; browser-header removal as session isolation; automatic cookie deletion after an asset response; claiming live readiness from localhost tests.

This decision changes the permitted library integration for the explicitly approved adapter only. It preserves the no-evasion, no-cookie-transfer, stop, retention and live-pilot requirements of [ADR 0005](0005-owner-directed-collection.md) and [ADR 0006](0006-collector-monorepo.md).

## Startup and resource containment refinement

The MCP browser lifecycle currently supports Windows only. A local forward proxy is started before Chrome and denies every HTTP/HTTPS request until the CDP guard and initial blank-tab check are complete. Chrome receives an explicit proxy with the implicit loopback bypass removed; QUIC and non-proxied WebRTC UDP are disabled. After arming, the proxy permits only the configured source origin and does not decrypt TLS or retain request/response data. Its listener, streams and pumps close before a bounded shutdown wait. A missing proxy has no direct fallback. Restored/unexpected tabs are rejected while the gate is still closed.

Chrome is created suspended with non-inheritable handles, assigned to a private Windows Job Object with kill-on-close, and then resumed using its returned primary-thread handle. The service retains the exact process/job handles. Job assignment failure retires only that suspended child; forced service termination closes the job handle and kills only that Chrome tree. A fixed loopback DevTools port is accepted only after its listener belongs to the exact child process; ordinary `--enable-automation` is retained. No DevTools marker is created or deleted by this launch path, enabling a marked, closed profile to reopen safely.

Static relays negotiate gzip, deflate and identity, stream raw 64-KiB chunks, and bound both compressed and decoded bytes independently. zlib output allocation is capped before decompression; unsupported/truncated encodings, concatenated streams and expansion beyond 8 MiB fail closed. At most two assets are fetched concurrently. A snapshot also has a 1-million-character serialized text bound and a 16-MiB aggregate encoded evidence bound. Attribute/style mutations remain conservatively fatal because they can change layout or overlays; the supported noise tolerance is for unrelated text updates, not arbitrary attribute churn. New security subtrees and a final security rescan invalidate capture. None of these tests establishes a real-source or cross-browser compatibility guarantee.

If owned-job release times out, the profile lease and job handle stay held; retry close or end the same service process to invoke kernel kill-on-close, then verify its owned tree exited before reopening. Do not delete profile locks or kill processes discovered by a profile scan. Startup failure cleanup attempts every owned handle close even when termination/wait fails, and preserves the original exception.

## Same-origin frames and guarded workers

The reader scans same-origin iframe/frame documents synchronously before it calls the main-page card reader. It permits at most 16 frames, depth 4 and 100,000 child text characters, preserving the main security scan limits. It checks child URL markers and visible security text, including nested and srcdoc frames. Child post cards are never collected. A loading/opaque/foreign document, object/embed/fenced frame or unenumerable shadow-frame tree refuses capture. The evidence record retains exact child document references and observes every child mutation; navigation, replacement or a new challenge invalidates capture.

Isolated DOM traversal cannot enumerate closed shadow roots, and window.length does not count their child frames on the tested Chrome. A separate CDP frame-tree check alone leaves a race before the isolated card read. The reader therefore waits for Debugger.paused before checking the authoritative tree and keeps source JavaScript paused throughout the synchronous security/card read and evidence capture, with an eight-second total bound. An inert owned statement triggers the pause on idle pages; no source prototype or browser fingerprint is modified. Debugger pause does not freeze every network/parser transition. A security-only preflight must first verify readyState=complete on the main and accessible child documents and retain exact Document references; the final synchronous reader checks those identities again before cards. Main navigation also destroys the isolated context used by that read. Loading, replaced or unenumerable documents fail closed. Unexpected resume, lost transport, pause timeout or failed resume closes the owned job. Normal resume is followed by policy/epoch validation. Native tests assert zero card reads and screenshots for open/closed shadow insertion and child navigation at pre-read seams, verify that scheduled source code waits for resume, reject a child with a confirmed pending HTTP response, and test pause failure paths. This behavior is qualified only for the installed synthetic Chrome runtime, not every browser version.

Earlier worker probes showed that target closure and stop-all-workers were insufficient containment: Chrome can restart a registered worker. The refined adapter uses a separate bounded CDP socket to the exact owned browser. Browser-level Fetch interception runs before arming and covers entry/update script loaders. Source dedicated/shared/service workers receive recursive auto-attachment, status observation and cache controls before Runtime resume. Browser-level Fetch guards every request, including dedicated/shared workers whose targets do not implement Fetch; service workers also receive per-session Fetch guards. Browser auto-attachment owns service workers while the page/worker sessions own related dedicated/shared workers, avoiding duplicate service-worker sessions. Unexpected page/opaque-frame targets fail closed.

Chrome can retain a service-worker target/session through a stop/restart and emit Inspector.targetReloadedAfterCrash rather than AttachedToTarget. The guard reinstalls interception before resuming that session. Synthetic acceptance deliberately delays re-arm and asserts the worker's first request remains uncontacted, across three consecutive restarts. Built-in Chrome workers stay paused; repeatedly closing them was rejected because it induced a restart loop. Worker socket loss and event/target bounds revoke the gate and close only the owned job.

Before arming, Fetch supplies an inert origin document while the source network gate remains closed and Network bypasses service workers. An awaited registration count and guarded target barrier must complete. Registrations are preserved; they no longer cause automatic profile refusal. Ordinary navigation enables worker handling only afterward. A synthetic pre-active worker exercises the closed startup gate. No registration, cookie, cache storage or profile data is deleted. Main-page and worker Network.responseReceived observers read only status/Retry-After to catch worker-generated/cache responses that have no Fetch response-stage event.

The [compatibility harness](../../../collector/scripts/test-mcp-compat.py) covers these paths and the separate script-loader/update and synthetic-response 429 seams. The deterministic update fixture registers a new script URL in the same scope. A same-URL registration.update() probe that emitted no request is unqualified, not evidence of success or a guard bypass. Chromium's browser FetchHandler is described in its [browser agent source](https://chromium.googlesource.com/chromium/src/+/refs/tags/143.0.7475.6/content/browser/devtools/browser_devtools_agent_host.cc); runtime receipts, not that source reference, qualify this installed Chrome. A worker entry-script redirect can make Chrome close the target during Network.enable. The adapter deliberately closes its owned job in that case; acceptance asserts the closed gate/process, zero destination requests and refusal of further snapshots. It does not wait for page JavaScript after the guard has stopped the browser. No Facebook profile or source was used, and this candidate makes no usable-Facebook-integration claim.

Socket-closure waiters and listener-completion callbacks revoke forwarding and terminate only the owned job immediately, even while Collector is idle. The transport cannot silently reconnect without its guard. Native idle-loss probes schedule a same-origin canary, abort a page, browser or worker-guard CDP socket and make no further RPC; the canary stays uncontacted. Pending Fetch/target tasks share a 64-task combined bound, worker commands at 64, and source target attachments/restarts at 32 per session; overflow poisons the session and closes the gate/job. A 200-request held-event fixture exercises that bound. These counters and evidence-byte limits are not a total Chrome or upstream CDP memory cap.

Profile command-line metadata alone does not establish a live owner. A matching process receives a fresh, zero-time exit check; terminated/gone processes are ignored, while live or inaccessible processes still refuse admission. The fresh process object avoids trusting an enumerator's cached exit status after PID reuse. On shutdown, the service retains wait handles for private-job members, verifies membership before waiting, and releases the lease only after both job accounting and those process signals show completion. A reused PID outside the job is neither waited on nor terminated. No profile-wide process cleanup is used.

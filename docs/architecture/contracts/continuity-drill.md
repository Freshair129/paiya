# สัญญาการทดสอบความต่อเนื่อง (O4)

หน้านี้ขยายแถว “ความต่อเนื่อง” ใน [สเปกสถาปัตยกรรม](../SPEC.md) ข้อ 7 ให้เป็น process ของ worker จุดจำลองการหยุด และสคริปต์ซ้อมที่รันได้บนเครื่องเจ้าของด้วยข้อมูลสังเคราะห์ ตามแถว O4 ใน [ROADMAP](../../delivery/ROADMAP.md) ใช้คู่กับ [สัญญาคิวค้นพบ](discovery-queue.md), [สัญญาการสำรอง](backup-and-restore.md), [สัญญางานลบ](revocation-and-purge.md) ข้อ 4 และ [สัญญาสุขภาพระบบ](system-health.md)

## 1. Worker สำหรับ fixture

- **`paiya worker run [--once] [--now <UTC ISO-8601>]`** เป็น process ที่วนทำงานตามลำดับนี้
  1. วางรอบตาม `schedule_due`
  2. จองงานด้วย `claim_next`
  3. รันงาน discover หรือ revisit ผ่าน adapter feed script จาก `PAIYA_FIXTURE_FEED_DIR`
  4. ปิดงาน (complete, fail หรือ cancel ตามสัญญาคิว)
- `--once` ทำหนึ่งรอบแล้วออก ส่วน `--now` ใช้ได้เฉพาะคู่กับ `--once` เพื่อกำหนดเวลาของรอบนั้น ใช้ในการซ้อมเครื่องหลับ
- ก่อนเริ่มต้องตรวจ purge log ด้วย `check_purge_log` แบบเดียวกับ serve และ MCP ถ้ามีคำสั่งลบค้างให้ออกด้วยรหัส 2 พร้อม `code: message` ตาม [สัญญางานลบ](revocation-and-purge.md) ข้อ 4
- worker ระยะ A รับเฉพาะ adapter fixture ไม่มีโค้ดเปิดแหล่งจริง
- เขียน log ตาม [สัญญาสุขภาพระบบ](system-health.md) ข้อ 1

## 2. จุดจำลองการหยุด

- ทำงานเฉพาะเมื่อตั้งครบสองค่า: `PAIYA_ALLOW_FAULT_INJECTION=1` และ `PAIYA_FAULT_POINT`
- `PAIYA_FAULT_POINT` มีสามค่า:
  - `after_media_write`: เขียนไฟล์ภาพแล้วแต่ยังไม่ commit
  - `after_ingest_commit`: commit observation แล้วแต่ยังไม่ปิดงาน
  - `before_job_complete`: ทำงานเสร็จแล้วแต่ยังไม่เรียก complete
- เมื่อถึงจุดที่ตั้งไว้ process ออกทันทีด้วย `os._exit(86)` ไม่ rollback และไม่ cleanup เพื่อจำลองไฟดับหรือ process ถูกฆ่า
- ถ้าตั้ง `PAIYA_FAULT_POINT` โดยไม่มี `PAIYA_ALLOW_FAULT_INJECTION=1` ให้ worker ปฏิเสธการเริ่มด้วยรหัส 2 เพื่อกันการตั้งค่าค้างไว้ในเครื่องใช้งานจริง

## 3. สคริปต์ซ้อม `scripts/continuity_drill.py`

- ทุกขั้นรันเป็น process แยกบนฐานข้อมูลและไดเรกทอรีชั่วคราวที่สร้างใหม่
- เมื่อจบให้ลบฐานและไดเรกทอรีชั่วคราว แล้วพิมพ์รายงาน JSON
- รหัสออก 0 เมื่อทุกข้อผ่าน

| ขั้น | วิธี | ผ่านเมื่อ |
|---|---|---|
| หยุดหลังเขียนภาพ | รัน worker ด้วย `after_media_write` แล้วรันซ้ำโดยไม่ตั้งค่า | observation, sale_events และ status facts ไม่ซ้ำ งานเดิมสำเร็จด้วยคีย์เดิม ไฟล์ภาพที่ไม่มีแถวอ้างถึงรายงานเป็นจำนวน orphan โดยไม่ลบ |
| หยุดหลัง commit | `after_ingest_commit` แล้วรันซ้ำ | ingest ซ้ำได้ผลเดิมตาม `capture_id` ไม่มีแถวหรือเหตุการณ์ซ้ำ งานปิดได้ |
| หยุดก่อนปิดงาน | `before_job_complete` แล้วรันซ้ำหลัง lease หมดอายุ | งานถูกจองใหม่และปิดได้ ไม่มีแถวหรือเหตุการณ์ซ้ำ |
| เครื่องหลับ | `--once --now T` แล้ว `--once --now T + 3 ชั่วโมง` | มี `capture_gaps` ชนิด `missed_slots` ครอบช่วงที่ข้าม รอบติดตามต่อมีหนึ่งรอบ และหน้าสุขภาพระบบแสดงช่วงขาด |
| restore และสิทธิ์ | สำรองตาม O1a → เพิกถอนและลบหนึ่ง grant → กู้ชุดก่อนลบลงปลายทางใหม่ → เปิด `paiya serve` บนพอร์ตชั่วคราวของปลายทางและ MCP stdio | ข้อมูลของ grant ที่ลบอ่านไม่ได้ทั้ง HTTP API ที่ UI ใช้และทุกเครื่องมือ MCP ข้อมูลที่ยังมีสิทธิ์อ่านได้ |

## 4. นอกขอบเขต

- การลบไฟล์ orphan หลังพ้นช่วงผ่อนผัน เป็นงานลบที่มีความเสี่ยงสูง สคริปต์นี้รายงานจำนวนเท่านั้น
- การตั้ง worker เป็น service หรือ task ของระบบปฏิบัติการ อยู่ใน runbook ของ O3
- การรันกับแหล่งจริง
